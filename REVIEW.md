# REVIEW.md

Defects found in the starter `app/main.py` (line numbers refer to the starter file). Examples assume shift 09:30-18:30 unless stated, and a server whose local time zone is UTC (as in most containers).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, L22 `MongoClient(...)` | No `tz_aware=True`: PyMongo returns naive datetimes. Mixing them with aware ones crashes, and `.timestamp()` on a naive value uses the server's local zone. | Subtracting a stored `punch_in` from an IST-aware shift end raises `TypeError: can't subtract offset-naive and offset-aware datetimes` -> 500. | `MongoClient(..., tz_aware=True)`; all instants are aware UTC internally and converted to epoch ms only at the API boundary. |
| 2 | module (whole file) | No indexes are created. Uniqueness of `emp_code` and of (`emp_code`, `date`) is not enforced, and list/analytics queries do collection scans. | `explain` on `GET /attendance` shows `COLLSCAN`; two concurrent creates both succeed (see #12, #17). | `ensure_indexes()` at startup (lifespan), idempotent: unique `emp_code`, unique (`emp_code`,`date`), (`date` desc, `emp_code`), (`emp_code`,`punch_in` desc), (`department`,`joined_on`), (`joined_on`). Retried from `/health` if MongoDB was down at startup. |
| 3 | `compute_late_minutes`, L35 | Shift start is built with `punch_in.replace(hour, minute)`, i.e. in whatever zone `punch_in` has (server-local or UTC), not IST. | Punch-in 10:05 IST passed as a UTC datetime (04:35Z) gives `0` instead of `35`. | Shift start is built from the attendance date + `shift_start` in IST (`shift_start_at`). |
| 4 | `compute_late_minutes`, L36-37 | Grace check is done on *floored minutes* (`minutes > 10`), so 10:01-10:59 after start counts as on time. R2 says strictly more than 10:00. | 09:40:30 -> starter `0`, expected `10`. (09:40:00 -> 0 and 09:40:01 -> 10 per R2.) | Compare *seconds*: late if `seconds > 600`, then `seconds // 60`. |
| 5 | `compute_late_minutes`, L35 | Overnight shifts: a punch-in after midnight is compared with 22:00 of the *same* calendar day, so it is never late. | Shift 22:00-06:00, punch-in 01:00 -> `0`, expected `180`. | Shift start is taken on the attendance date (R1), which for after-midnight punches is the previous day. |
| 6 | `compute_work_hours`, L41 | `round(x, 2)` is float/banker's rounding, not half-up (R4). | 2 h 15 m 18 s = 2.255 h -> starter `2.25`, expected `2.26`. | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`. |
| 7 | `compute_overtime`, L47 | No 30-minute minimum (R3): any positive overtime is returned. | Punch-out 18:35 -> starter `5`, expected `0`. | Return the floored minutes only when `>= 30`, else 0. |
| 8 | `compute_overtime`, L46 | Overnight shift end is placed on the shift's start date instead of the next day. | Shift 22:00-06:00 on 2026-07-06, punch-out 07-07 06:40 -> starter `1480`, expected `40`. | `shift_end_at()` adds one day when `shift_end <= shift_start`. |
| 9 | `EmployeeIn`, L53-60 | No validation: any `emp_code`, email, empty name, `"9:3x"` shift times, `shift_start == shift_end`, invalid `joined_on`. | `POST /employees` with `shift_start: "abc"` returns 201; the next punch-in for that employee crashes in `split(":")` -> 500. | Pydantic constraints from the contract: `^EMP\d{4,6}$`, lengths, email pattern, `HH:MM` pattern, real `YYYY-MM-DD` date, model validator `shift_start != shift_end` -> 422. |
| 10 | `PunchInIn`, L65 | `punched_at: Optional[int]` is lax: accepts `"1783312500000"` (string), `1783312500000.0` (float) and seconds (`1783312500`, read as 1970). | Body `{"punched_at": 1783312500}` -> 201 with a 1970 date instead of 422. | `EpochMs = Annotated[int, Field(strict=True, ge=100000000000, le=4102444800000)]`. |
| 11 | `PunchInIn`, L66 | `status: str` accepts `ABSENT`, `LEAVE` or any text. | `{"status": "ABSENT"}` -> 201; `{"status": "foo"}` -> 201. | `Literal["PRESENT","WFH","ON_DUTY"]` -> 422. |
| 12 | `health`, L73-74 | Always returns 200 without talking to MongoDB. | Stop MongoDB: `/health` still says ok; the grader starts testing a dead app. | `client.admin.command("ping")`, 503 on failure; short `serverSelectionTimeoutMS` so it answers quickly. |
| 13 | `create_employee`, L79-83 | Check-then-insert: two concurrent creates with the same `emp_code` both pass the `find_one` and both insert. | 10 parallel POSTs with one code -> several 201s and duplicate documents. | Unique index + catch `DuplicateKeyError` -> 409. No pre-check. |
| 14 | `create_employee`, L82 + L85 | `created_at = datetime.now()` is naive server-local time (stored as if UTC), and the response returns a datetime, not epoch ms. | On an IST machine `created_at` is 5:30 h off; response shows `"2026-..T.."` string. | `now_utc()` (aware, whole seconds); `employee_out()` returns `created_at` as epoch ms. |
| 15 | `list_employees`, L93 | `skip = page * page_size`: page 1 skips the first page. | 25 employees, `GET /employees` -> 5 items (21-25) instead of 20. | `skip = (page - 1) * page_size`. |
| 16 | `list_employees`, L94 | `total` counts the whole collection, ignoring the department filter (R10). | `?department=Sales` with 3 of 10 employees -> `total: 10`. | `count_documents(q)` with the same filter. |
| 17 | `list_employees`, L89/L95 | No sort (contract: `emp_code` ascending) and no bounds on `page`/`page_size`. | Order changes between calls; `page_size=0` returns everything (`limit(0)` = no limit); `page=-1` -> negative skip -> 500. | `.sort("emp_code")`; `page >= 1`, `1 <= page_size <= 100` -> 422 otherwise. |
| 18 | `punch_in`, L101 + L113 | Unknown employee is not handled: `emp` is `None` and `emp["shift_start"]` raises. | `{"emp_code": "EMP9999"}` -> 500 instead of 404. | `get_employee_or_404()` before anything else. |
| 19 | `punch_in`, L102-103 | `datetime.fromtimestamp(ms/1000)` uses the server's local zone, keeps milliseconds (R1 says truncate) and the date is the server-local date, not the IST date. | Punch-in 02:00 IST on 07-06 on a UTC server -> `date: "2026-07-05"`; late computed against 09:30 UTC. | `ms_to_dt()` = `fromtimestamp(ms // 1000, UTC)`; date from `attendance_date()` in IST. |
| 20 | `punch_in`, L103 | Overnight shift rule (R1) missing: a punch-in before `shift_end` belongs to the previous day's shift. | Shift 22:00-06:00, punch-in 07-07 01:00 -> starter date `2026-07-07`, expected `2026-07-06`. | `attendance_date()` subtracts a day for overnight shifts when the IST time is earlier than `shift_end`. |
| 21 | `punch_in`, L104-118 | Check-then-insert race: two identical punch-ins at the same instant both pass `find_one` and both insert. | 10 parallel identical punch-ins -> several 201s; duplicate (`emp_code`,`date`) records. | Unique (`emp_code`,`date`) index; `insert_one` and map `DuplicateKeyError` -> 409. |
| 22 | `punch_in`, L102 | `if body.punched_at` is a truthiness test, so `0` means "now". | Minor; `punched_at: 0` silently becomes the current time. | `is not None` test (and 0 is now rejected by validation anyway). |
| 23 | `punch_in`, L119-121 | Response leaks `id` (the MongoDB `_id`) and returns `punch_in` as a datetime string, not epoch ms. | Response contains `"id": "66a..."` and `"punch_in": "2026-07-06T10:05:00"`. | `record_out()` builds the contract shape: no id, instants as epoch ms. |
| 24 | `list_attendance`, L144-147 | Loads every matching document into Python, sorts and slices in memory. | At ~100k records the request is slow and memory-heavy; `explain` shows a `COLLSCAN`. | `find(q).sort(...).skip(...).limit(...)` in MongoDB, backed by the (`date` desc, `emp_code`) index; `count_documents(q)` for `total`. |
| 25 | `list_attendance`, L145 | Sort is only by `date` desc; the contract also requires `emp_code` asc as a tie-breaker. | Records of the same date come back in insertion order. | `sort([("date", -1), ("emp_code", 1)])`. |
| 26 | `list_attendance`, L127-131 | No validation: invalid dates are compared as strings, `date_from > date_to` is accepted, any `status` text accepted, no page bounds. | `?date_from=2026-07-08&date_to=2026-07-01` -> 200 with empty list instead of 422; `?status=FOO` -> 200. | `date` typed params, `Literal` status, page bounds, explicit 422 for `date_from > date_to`. |
| 27 | `list_attendance`, L148-149 | Response contains `id` and raw datetimes (`punch_in`, `punch_out`, `history[].at`, dates inside `history[].changes`). Legacy records missing `half_day`/`history` are returned without those fields. | Items have `"id"` and ISO strings; record #9 of the sample has no `history` key in the response. | `record_out()`: no id, epoch ms everywhere (including inside `changes`), defaults `half_day=false`, `history=[]`, minutes `0`. |

**Looked at and not a defect**

- `load_dotenv()` (L20): by default it does not override variables that are already set, so real environment variables already win. Kept (made explicit with `override=False`).
- `IST = timezone(timedelta(hours=5, minutes=30))` (L25): correct.
- `$gte` / `$lte` on `date` strings (L139-141): correct, because `YYYY-MM-DD` strings sort the same way as dates and the contract says the bounds are inclusive.
- `status_code=201` on `POST /employees` and punch-in: correct per contract.
- The work-hours formula itself, seconds / 3600 (L41): correct; only the rounding was wrong (#6).
- Reading `MONGO_URI` / `MONGO_DB` with local defaults (L22-23): fine; nothing is hard-coded for the grader.
